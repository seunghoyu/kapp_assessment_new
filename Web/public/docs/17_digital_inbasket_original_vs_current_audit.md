# 17 디지털 인바스켓: 원본 vs 현재 대조·검수 및 추가 변환 목록

> **목적**: 시작 버튼 클릭 후 나오는 시뮬레이션 화면이 원본(digital_inbasket)과 차이가 나는 부분을 하나하나 대조·검수하고, **변환하기 전에** 어떤 것을 추가로 변환해야 하는지 확인하기 위한 문서입니다.  
> 실행(변환 작업) 전에 본 문서를 기준으로 누락·차이를 정리했으며, 학습자 LMS 드롭다운에서 확인할 수 있습니다.

---

## 1. 개요

| 구분 | 원본 (digital_inbasket) | 현재 (Next.js 학습자 LMS) |
|------|-------------------------|----------------------------|
| **위치** | `digital_inbasket/` (HTML + js/simulation.js 등) | `app/app/diagnosis/inbasket-simulations/` + `data/.../inbasketQuestions.json` |
| **문항 수** | API/DB 기준 48개 (타입당 여러 개) | JSON 48개 반영 가능, 타입당 3개씩 구성 |
| **시뮬레이션 타입** | 16가지 | 16가지 (동일) |
| **문제 제기** | 시작 눌렀을 때 화면이 원본과 너무 다름. 전부 다 들어가야 함. | 타입별로 UI·옵션·데이터 구성이 원본 대비 누락·단순화된 부분 있음 |

아래는 **타입별로 원본에 있는 요소 vs 현재 구현 vs 추가 변환 필요 사항**을 정리한 검수표입니다.

---

## 2. 타입별 대조·검수표

### 2.1 이메일 관리

| 항목 | 원본 | 현재 | 추가 변환 필요 |
|------|------|------|----------------|
| 이메일 목록 | 5통 고정 (이사회/고객사/재무/마케팅/영업) | 문항 1통 + 동일 4통 고정 (5통) | 없음 (현재가 문항 반영으로 더 적합) |
| 좌측 폴더 | 받은편지함, 중요, 보낸편지함 | 동일 | 없음 |
| 액션 버튼 | 답장/전달/보관/삭제 | 동일 | 없음 |
| 우선순위 | 긴급/중요/보통 | 동일 | 없음 |
| 처리 완료 표시 | 녹색 체크 | 동일 | 없음 |

**결론**: 유지. 변환 불필요.

### 2.2 메신저 대응

| 항목 | 원본 | 현재 | 추가 변환 필요 |
|------|------|------|----------------|
| 채널 사이드바 | 보라색, #긴급-요청 등 | 구현 여부 확인 | 채널 리스트·선택 상태 원본과 동일하게 |
| 메시지 수 | 4건 (영업/회계/마케팅/인사) | 문항 기반 또는 고정 4건 | 문항 1건 + 나머지 3건 등 원본 톤 유지 |
| 처리 옵션 | 즉시처리/위임/대기/정보수집 | 동일 | 없음 |
| 우선순위 | 1~4순위 | 동일 | 없음 |
| 긴급 메시지 강조 | 빨간 배경·테두리 | 동일 | 없음 |

**결론**: 채널 UI·메시지 구성이 원본과 동일한지 확인 후, 누락 시 보강.

### 2.3 보고서 작성

| 항목 | 원본 | 현재 | 추가 변환 필요 |
|------|------|------|----------------|
| 부서 수 | **6개** (영업/마케팅/개발/인사/재무/고객지원) | **4개** (영업/마케팅/재무/인사) | **6부서로 확대**, 개발·고객지원 추가 |
| 부서 상태 | 제출/부분제출/미제출 | 제출완료/대기중 | **부분제출** 추가, 원본 3단계 반영 |
| 리본 메뉴 | 폰트·크기, B/I/U, 차트/표/이미지 | 없음 | **리본 메뉴 추가** (폰트, 굵게/기울임/밑줄, 차트/표/이미지 버튼) |
| 부서별 입력 | 긴급도(높음/보통/낮음), 대응방안(즉시독촉/기존자료/제외/간략요약), 메모, 결정완료 | 없음 | **부서별 긴급도·대응방안·메모·결정완료** UI 추가 |
| 수집 진행률 | 진행률 바 + "0 / N 부서 결정 완료" | 없음 | **진행률 바·텍스트** 추가 |
| 중앙 편집 | A4 보고서, 개요·부서별 현황 섹션 | 단순 textarea + question.content | **A4 스타일·섹션 구조** 원본에 맞게 (개요, 부서별 데이터 현황 등) |

**결론**: **보고서 작성은 추가 변환 필수.** 6부서, 리본, 부서별 의사결정, 진행률, A4 레이아웃 전부 반영 필요.

### 2.4 일정 관리

| 항목 | 원본 | 현재 | 추가 변환 필요 |
|------|------|------|----------------|
| 시간대 그리드 | 9시~20시 타임라인 그리드 | 없음 | 선택: **타임라인 그리드** 추가 시 원본과 동일한 느낌 |
| 14시 충돌 | 3개 회의 같은 시간대 시각화 (빨간 배경 등) | 3개 회의 카드로 표시 | 현재도 충돌 인지 가능. 그리드 추가 시 더 명확 |
| 회의 카드 | 제목, 시간, 장소, 참석자, 자료 | 제목, 시간, 장소, 참석자 | 자료 필드 선택 추가 |
| 결정 옵션 | 직접 참석/대리 참석/시간 변경/불참 | 동일 | 없음 |

**결론**: 현재만으로도 동작 가능. **타임라인 그리드**는 원본 완전 일치 시 추가 권장.

### 2.6 위기 관리

**결론**: **상황판 추가**, **예산을 체크박스 4항목+총합**으로 변경. 카운트다운은 기획에 따라 선택.

**결론**: 상단 예산 + 우측 ROI 패널 추가. 캠페인 성과 지표 원본과 동일화.

### 2.16 생산관리

| 상단 현황 | 4라인 상태 요약 (정상/주의/긴급/시험) | 헤더만 간단 | **상단 요약 블록** (원본처럼 4라인 한눈에) |

**결론**: 상단 4라인 요약 + 라인2 상세 수치·문구 + 우측 가이드 반영.

## 3. 추가 변환 시 우선 반영 목록 (실행 전 확인)

변환 작업 시 아래 순서로 반영하면 원본과의 차이를 빠르게 줄일 수 있습니다.

1. **보고서 작성**: 6부서, 리본 메뉴, 부서별 긴급도·대응방안·메모·진행률, A4 편집 구조.
2. **위기 관리**: 예산을 4개 체크박스+금액+총합으로 변경, 좌측 상황판 추가.
3. **법무 검토**: 제9조·제11조 추가 (총 6조항).
4. **마케팅캠페인**: 상단 예산 현황, 우측 ROI 패널.
5. **생산관리**: 상단 4라인 요약, 라인2 상세 수치(납기/재고/손실), 우측 가이드.
6. **글로벌 협업**: 4지사 타임존·지도, 3가지 문제 해결 UI.
7. **인사/재무/고객/윤리/전략/디지털**: 각 타입별로 원본 simulation.js·simulation-extended.js와 한 번 더 대조 후, 누락된 블록·옵션·텍스트 추가.
8. **일정 관리**: (선택) 9~20시 타임라인 그리드.
9. **통합 업무**: 4채널 탭·통계 패널 확인 및 보강.

## 4. 데이터(문항) 측면

- **inbasketQuestions.json**은 이미 48개 문항(타입당 3개)이 들어가 있으면, **시작 눌렀을 때 문항별로 다른 제목·발신·내용**이 나오는 구조는 갖춰져 있음.
- 문제는 **시뮬레이션 화면(컴포넌트) 안**에 원본에 있던 **UI 블록·옵션·문구가 빠져 있는 것**이므로, 위 검수표대로 **컴포넌트 단위로 추가 변환**하면 됩니다.

  - `digital_inbasket/js/simulation-extended.js` (인사·재무·고객·윤리·전략 확장 UI)
