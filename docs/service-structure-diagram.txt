# KAPP 서비스 구조도 (수정 반영본) — React Flow 초안용
# 최종 보강: 2026-03 — 디지털 인바스켓 48문항·AI 워크플로우 **기능명세 부록** 추가.

※ **본문**: 기획자도 이해할 수 있도록 기능·화면 중심 서술.
※ **하위 [개발]**: 개발자용 상세 — 파일 경로, 상태/키 이름, 데이터 구조, 컴포넌트·props 보완.
※ JSON 샘플이 있는 항목은 구조도에서는 **하나의 노드**로 표현 (상세는 노드 클릭/툴팁 등으로 분리 전달).
※ React Flow로 구현 시 Cursor에 **단계별 프롬프트**로 나눠 전달할 것 (본 문서 하단 참고).

- 진단 step 1: 산업·세부직무는 단일 모달(IndustrySelectModal) 2단계 슬라이드. 1단계 산업군 그리드(industry_tree 20개)→[선택]→2단계 분야·직무(job_taxonomy_payload: categories+jobs)→[선택] 시 onSelect(major,jobName), 모달 닫기. 세부 직무는 읽기전용 input, 별도 직무 전용 모달 없음.

- 진단 step 5: 헤더 "전체 문항", 진행률 게이지(테스트 환경 좌측), 테스트 환경 클릭 시 직무 필터 드롭다운만 노출.

- 진단 step 6: 설명 영역 제거, "결과 확인하기" 버튼만 가운데 → /app/dashboard.
- 진단 상단 헤더: sticky 고정. 디지털 인바스켓 제목 옆에 HelpCircle 버튼(텍스트 바로 우측).
- 대시보드: 탭 2개만 — 내 역량 | 성장 로드맵. (시장·경쟁력 탭 없음, 시장 포지션은 내 역량 하단 섹션.)
- 성장 로드맵: 카드 현재/3년 후/5년 후, 확률(%) 문구 미표시. 산업군 가상프론트 21개, 직무 1~4 더미.

A.1 목적·측정 관점
--------------------------------------------------------------------------------
- 디지털 인바스켓은 받은편지함·메신저·보고·일정 등 **업무 알림이 동시에 유입**된다는 가정 하에서, 학습자가 **우선순위 판단·채널별 대응·의사결정**을 연습하는 단계(step 5).
- 문항은 **16개 시뮬레이션 타입(category)** × **타입당 3문항** = **총 48문항**으로 구성된다.
- 각 문항은 `jobCategory`로 **직무 필터**(테스트 환경)와 표시 아이콘·테이블 정렬에 쓰인다.
- **AI 워크플로우**는 별도 1건으로 목록 하단에 붙으며, 산업(form.industry)에 따라 시나리오·선지가 바뀐다.

**answers 스키마(인바스켓 관련)**  
- `answers.etray: Record<string, string>` — 키는 **인바스켓 문항 id**(예: inbasket_email_1). 값이 비어 있지 않으면 해당 문항 **완료**(현재 구현은 `"completed"` 문자열 저장).  
- `answers.ai: number | null` — AI 워크플로우에서 선택한 **옵션 배열 인덱스**(0~3). null이면 미완료.

**진행률**  
- `total = inbasketQuestions.length + (aiWorkflow ? 1 : 0)`  
- `completed = (etray에 값이 있는 문항 수) + (answers.ai != null ? 1 : 0)`
