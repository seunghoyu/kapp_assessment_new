목표
STEP 1에서 생성된 **Data Inventory** 를 기반으로
서비스 ERD 설계를 위한 **엔티티 후보(Entity Candidates)** 를 생성한다.

현재 단계에서는 ERD를 생성하지 않는다.
목표는 **서비스 데이터 모델의 핵심 엔티티를 정의하는 것**이다.

---

실행 규칙

1. 반드시 **단계별로 순서대로 진행한다**
2. 각 단계가 끝나면 **결과를 출력하고 멈춘다**
3. 다음 단계는 내가 **"continue"** 라고 할 때 진행한다
4. 추측하지 말고 **STEP 1 Data Inventory 기반으로만 작업한다**

---

입력 데이터

STEP 1에서 생성된 **Data Inventory**

---

STEP 2-A
Data Inventory에 있는 데이터 목록을 분석하여
**ERD 엔티티 후보를 추출**한다.

선별 기준

ERD 엔티티가 되는 데이터

* 서비스에서 지속적으로 저장되는 데이터
* 사용자 또는 시스템 상태를 표현하는 데이터
* 서비스 핵심 기능에 사용되는 데이터

제외 대상

* UI 상태 데이터
* 계산 결과 데이터
* 임시 데이터
* 컴포넌트 내부 데이터

출력 형식

| Entity (영문) | 한글명 | 설명 | 데이터 출처 |

---

STEP 2-B
STEP 2-A에서 생성된 엔티티 후보를 검토하여
**중복 엔티티를 정리**한다.

정리 규칙

* 의미가 같은 데이터 통합
* 이름만 다른 데이터 통합
* 상위 개념으로 정리

출력 형식

| Entity | 한글명 | 설명 |

---

STEP 2-C
서비스 구조를 기준으로 엔티티를 **도메인 그룹으로 분류**한다.

도메인 예시

* 사용자 도메인
* 진단 도메인
* 문항 도메인
* 조직 도메인

출력 형식

| Domain | Entity | 한글명 | 설명 |

---

STEP 2-D
최종 **서비스 ERD 엔티티 목록**을 생성한다.

출력 형식

| Entity | 한글명 | 설명 |

이 목록은 이후 단계에서

* 엔티티 속성 정의
* 엔티티 관계 정의
* ERD 생성

에 사용된다.

---

주의

현재 단계에서는 다음 작업을 하지 않는다.

* 엔티티 속성 정의
* 엔티티 관계 정의
* ERD 생성
* DBML 작성
