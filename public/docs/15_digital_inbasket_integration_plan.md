# 디지털 인바스켓 Next.js 통합 기획·분석 문서

> 학습자 LMS(B2C)에 디지털 인바스켓을 어떻게 넣을지, 원본 `digital_inbasket` 폴더의 구조·디자인은 어떤지, 앱에 넣을 때 무엇을 어떻게 바꿀지 비개발자도 이해할 수 있도록 정리한 문서입니다.

---

## 1. 학습자 LMS에서의 진행 방식 (어떻게 진행할지)

### 1.1 현재 KAPP 진단 흐름

지금 학습자가 겪는 흐름은 다음과 같습니다.

1. **로그인** → 소비자 대시보드(`/app`) 진입  
2. **KAPP 진단** 메뉴 클릭 → 진단 페이지(`/app/diagnosis`)  
3. 단계 순서: **시작 → 정보 입력 → 지식 → 적용 → 성과 → 디지털 인바스켓 → AI 워크플로우 → 결과**  
4. **디지털 인바스켓**은 **5단계**에서만 등장하며, 현재는 “이메일 목록 + 본문 보기 + 액션(열기/답장/전달/보관)” 형태로만 구성되어 있습니다.

### 1.2 통합 후 진행 방식 (목표)

- **디지털 인바스켓 단계(5단계)** 에서, 원본에 있던 **16가지 시뮬레이션 타입**을 모두 사용할 수 있게 합니다.
- **가상 프론트 단계**에서는 직무/산업 매핑 없이 **16가지 시뮬레이션을 전부 목록으로 노출**하고, 학습자가 원하는 문항을 골라 진행합니다.
- 나중에 **직무·산업 매핑**을 넣을 때는, “이 직무/산업이면 이 타입만 보이게” 같은 식으로 목록을 필터링하면 됩니다. 지금 문서는 “전부 보여주는” 기준으로 작성합니다.

### 1.3 사용자 관점 흐름 (통합 후)

1. 학습자가 진단을 진행하다가 **5단계(디지털 인바스켓)** 에 도달합니다.
2. 화면에는 **16가지 시뮬레이션 타입**이 카드나 목록 형태로 보입니다.  
   (예: 이메일 관리, 메신저 대응, 보고서 작성, 일정 관리, … 생산 라인 관리)
3. 학습자는 **여러 개**를 순서대로 풀 수 있습니다.  
   (지금은 “여러 개 보여주고, 나중에 매핑으로 줄일 예정”이므로, 가상 프론트에서는 16개 모두 선택 가능하다고 보면 됩니다.)
4. 각 문항(시뮬레이션)을 선택하면:
   - **10분 타이머**가 있는 시뮬레이션 화면으로 들어가고,
   - 해당 타입에 맞는 UI(이메일 클라이언트, 캘린더, 위기 대응판 등)가 표시되며,
   - 학습자가 선택·입력한 내용은 **화면에서만 사용**하고, **별도 저장은 하지 않습니다.** (요구사항 반영)
5. “다음 단계로” 또는 “완료”를 누르면 **6단계(AI 워크플로우)** 로 넘어갑니다.

정리하면, **“진단 5단계 = 디지털 인바스켓”** 이고, 그 안에서 **16가지 시뮬레이션을 모두 목록으로 보여 주고, 여러 개를 풀 수 있게** 하는 흐름입니다.

## 2. 원본 digital_inbasket 폴더 분석

원본은 **단독 웹(HTML + CSS + JS)** 로 동작합니다. 외부 API(문항 조회 등)를 쓰도록 되어 있지만, Next 앱으로 가져올 때는 **데이터는 JSON/더미로** 넣고, **화면과 로직만** 가져옵니다.

### 2.1 폴더 구조

| 파일/폴더 | 역할 (쉽게 말하면) |
|-----------|---------------------|
| **index.html** | “문항 목록 페이지”. 직무 필터 버튼(12개) + 문항 카드 그리드 + 상세 보기 모달. |
| **simulation.html** | “시뮬레이션 실행 페이지”. 상단 진행률·타이머, 가운데 타입별 UI, 하단 “완료” 버튼. |
| **js/main.js** | 문항 목록 불러오기, 직무별 필터, 카드 표시, 모달, “시뮬레이션 시작” 시 `simulation.html?id=문항ID` 로 이동. |
| **js/simulation.js** | 문항 타입(category)에 따라 **16가지 UI** 중 하나를 골라 화면을 채움. 이메일·메신저·보고서·일정·위기·법무·인사·재무 등 각각 다른 레이아웃. |
| **js/simulation-extended.js** | 인사·재무·고객·윤리·전략 등 **일부 타입**의 상세 UI를 추가로 그리는 함수들. |
| **js/simulation-marketing-meeting.js** | 마케팅 관련 시뮬레이션용 추가 스크립트. |
| **README.md** | 16가지 시뮬레이션 설명, 직무 분류, 데이터 구조 등. |

### 2.2 index.html 분석

- **역할**: 디지털 인바스켓 **문항 목록 화면**.
- **상단**
  - 그라데이션 헤더(보라~남색 계열), “디지털 인바스켓” 타이틀, “전체 문항 수” 표시.
- **직무 선택**
  - 12개 버튼(전체, 경영/기획, 커뮤니케이션, … 생산/운영). 클릭 시 해당 직무 문항만 필터.
  - 버튼은 “알약(pill)” 형태, 선택 시 보라 그라데이션.
- **문항 카드**
  - 그리드(1~3열 반응형). 카드마다 우선순위(긴급/보통/낮음)에 따라 **색 그라데이션** (빨강, 파랑, 연한 그린 등).
  - 카드 내용: 제목, 발신자, 날짜, 카테고리, 내용 일부.
  - 버튼: “상세보기”(모달), “시작”(simulation.html로 이동).
- **모달**
  - 문항 상세(제목, 발신자, 날짜, 본문, 첨부). “시뮬레이션 시작” / “기본 응답 작성”.
- **스타일(CSS)**
  - 헤더: `linear-gradient(135deg, #667eea 0%, #764ba2 100%)` (보라~남보라).
  - 직무 버튼: 기본 흰색/회색 테두리, 호버 시 보라, 선택 시 그라데이션.
  - 카드: 흰 배경, 둥근 모서리, 그림자, 호버 시 살짝 떠오르는 효과.
  - 우선순위별: 긴급=빨강 계열, 보통=파랑 계열, 낮음=연한 그린/핑크.

**데이터**: `main.js`에서 `fetch('tables/questions?limit=100')` 로 문항을 가져옵니다. Next 앱에서는 이 API 대신 **JSON/더미 데이터**를 사용합니다.

### 2.3 simulation.html 분석

- **역할**: **시뮬레이션 한 건**을 실행하는 페이지.
- **공통 UI**
  - 상단: 진행률 바(0~100%), “진행률: 0%” 텍스트, “목록으로” 버튼.
  - 그 다음: 보라 그라데이션 헤더 카드(“디지털 인바스켓 시뮬레이션”, 설명, **10분 타이머**).
  - 가운데: `id="simulation-content"` 인 영역 하나. 여기에 **타입별로 다른 UI**가 채워짐.
  - 하단: “완료하고 다음 단계로” 버튼.
- **스타일**
  - `gradient-bg`: 보라 그라데이션.
  - 이메일 목록: 호버/선택 시 배경색·왼쪽 테두리로 선택 강조.

**동작**: 주소에 `?id=문항ID` 가 있으면 `simulation.js`가 해당 문항을 불러와 `category`(이메일 관리, 메신저 대응 등)에 따라 `renderEmailManagement`, `renderMessengerApp` 등 **16개 중 하나**를 호출해 `simulation-content` 안에 HTML을 채웁니다.

### 2.4 main.js 분석 (동작 요약)

- **문항 로드**: `fetch('tables/questions?limit=100')` → 받은 데이터로 카드 그리드 표시.
- **직무 매핑**: 문항의 `category`(이메일 관리, 메신저 대응, …)를 12개 직무(경영/기획, 커뮤니케이션 등)로 매핑해 필터/개수 표시.
- **필터**: 직무 버튼 클릭 시 해당 직무 문항만 표시.
- **상세 모달**: 문항 ID로 `fetch('tables/questions/{id}')` 후 모달에 제목·발신자·날짜·본문·첨부 표시.
- **시뮬레이션 시작**: `window.location.href = 'simulation.html?id=' + 문항ID` 로 이동.

Next 앱에서는 **페이지 이동 대신**, 같은 진단 페이지 안에서 “5단계일 때 목록 보여 주기 → 문항 선택 시 같은 페이지 내에서 시뮬레이션 영역만 전환”하는 방식으로 바꿀 수 있습니다.

### 2.5 simulation.js 분석 (동작 요약)

- **진입**: `simulation.html` 로드 시 URL에서 `id` 읽음 → `fetch('tables/questions/' + id)` 로 문항 조회.
- **타이머**: 10분(600초) 카운트다운, 1초마다 화면 갱신.
- **타입별 렌더링**: `question.category` 값에 따라 다음 16개 함수 중 하나 호출:
  1. 이메일 관리 → `renderEmailManagement` (Outlook 스타일 목록+본문+답장/전달/보관 등)
  2. 메신저 대응 → `renderMessengerApp` (Slack/Teams 스타일 채널+메시지+처리 옵션)
  3. 보고서 작성 → `renderDocumentEditor` (리본 메뉴+부서 데이터+보고서 편집 영역)
  4. 일정 관리 → `renderCalendarApp` (시간대 그리드+회의 충돌+참석/대리/변경 등)
  5. 통합 업무 → `renderProjectDashboard` (이메일/전화/SNS/메신저 탭+문의 목록+처리 옵션)
  6. 위기 관리 → `renderEmergencyCenter` (상황판+의사결정 단계+예산 등)
  7. 글로벌 협업 → `renderCollaborationPlatform` (지도+타임존+회의 조율 등)
  8. 법무 검토 → `renderContractReview` (조항 목록+계약서 뷰어+의견 선택)
  9. 디지털 활용 → `renderToolSelection` (AI 도구 비교+예산+도입 결정)
  10. 인사 관리 → (simulation-extended) 조직도+갈등 해결 옵션
  11. 재무 관리 → (simulation-extended) 부서별 예산 슬라이더+배분
  12. 고객 관리 → (simulation-extended) VIP 프로필+이슈+대응 전략
  13. 윤리 경영 → (simulation-extended) 제보 정보+워크플로우 단계
  14. 전략 기획 → (simulation-extended) M&A 매트릭스 등
  15. 마케팅캠페인 → `renderCampaignDashboard` (캠페인 카드+예산/성과+조치)
  16. 생산관리 → `renderProductionControl` (라인별 상태+의사결정 옵션)

각 함수는 **문항 데이터(question)**를 받아, `simulation-content` 안에 **해당 타입 전용 HTML 문자열**을 넣고, 버튼/선택 시 `userResponses` 등 전역 변수에 값을 쌓습니다. (현재는 응답 저장 API가 있지만, 요구사항상 “저장하지 않음”이므로 앱에서는 이 부분을 제거하거나 옵션으로 둡니다.)

### 2.6 CSS·디자인 요약 (원본)

| 구분 | 원본 스타일 |
|------|-------------|
| **전체 분위기** | 보라·남보라 그라데이션, 연보라/연파랑 배경. |
| **헤더** | 보라 그라데이션 배경, 흰 글씨, 둥근 아이콘 영역. |
| **버튼** | 그라데이션(보라→파랑, 초록→청록), 흰 글씨, 그림자. |
| **카드** | 흰 배경, 둥근 모서리, 큰 그림자, 호버 시 위로 살짝 이동. |

## 3. 앱에 넣을 때 무엇을 어떻게 바꿀지

### 3.1 “그대로 가져오는 것” vs “바꾸는 것”

- **가져오는 것**
  - **16가지 시뮬레이션의 기능과 흐름**: 이메일 클릭→본문→액션, 메신저 채널→메시지→처리, 일정 그리드→회의 선택→결정 등 **화면 구성과 선택지 구조**.
  - **직무 12개 분류**와 **문항–직무 매핑** 로직.
  - **10분 타이머**, **진행률 표시**, **“완료/다음으로”** 같은 진행 방식.
  - 문항 데이터가 가진 **필드 개념**(제목, 발신자, 날짜, 우선순위, 본문, 카테고리, 첨부 등).

- **바꾸는 것**
  - **파일 형태**: HTML/CSS/JS → **Next.js(React) 컴포넌트 + Tailwind**.
  - **데이터 출처**: `fetch('tables/...')` API → **앱 내 JSON/더미 데이터** (이후 LLM 연동은 별도 작업).
  - **페이지 구조**: `index.html` + `simulation.html` 두 페이지 → **진단 5단계 한 화면 안**에서 “목록 뷰”와 “시뮬레이션 뷰” 전환.
  - **디자인**: 아래 3.2절처럼 **B2C(마이 대시보드) 톤앤매너**로 통일.

### 3.2 디자인 톤앤매너 맞추기 (B2C / app/dashboard 느낌)

현재 **app/dashboard**와 **app/diagnosis**는 다음과 같은 느낌입니다.

- **배경**: 흰색·밝은 회색(`gray-50`) 위주, 화려한 그라데이션 없음.
- **카드**: `bg-white`, `border border-gray-200`, `rounded-xl`, `shadow-sm`.
- **강조색**: **파랑 계열**(`blue-600`, `blue-700`)을 주로 사용.
- **버튼**: `bg-blue-600 text-white`, `rounded-lg`, 호버 시 `bg-blue-700`.
- **헤더/섹션**: `border-b border-gray-100`, `bg-gray-50/50`, 제목은 `text-gray-800` 등.
- **아이콘**: Lucide React (Inbox, Mail, MessageSquare 등). Font Awesome 대신 Lucide로 통일 가능.

따라서 **디지털 인바스켓만** 다음처럼 바꿉니다.

| 원본 | 앱에서 |
|------|--------|
| 보라·남보라 그라데이션 헤더 | 흰색 또는 연한 회색 배경, 파란색 포인트만 사용 (예: “디지털 인바스켓” 옆 아이콘만 blue-600). |
| 직무 pill 그라데이션(선택 시) | 선택 시 `bg-blue-600 text-white`, 비선택 시 `bg-white border border-gray-200 text-gray-700`. |
| 문항 카드 우선순위 그라데이션(빨강/파랑/연녹) | 배경은 흰색 유지, 우선순위는 **작은 뱃지**로만 표시 (긴급=빨간 뱃지, 보통=파란 뱃지, 낮음=회색 뱃지). |
| “상세보기”/“시작” 그라데이션 버튼 | `bg-blue-600` / `border border-gray-300` 같은 단색 버튼. |
| simulation 상단 그라데이션 헤더 | 진단 카드와 동일한 `bg-white border border-gray-200` 상단 바 + 타이머만 강조. |
| Font Awesome | Lucide 아이콘으로 교체. |

이렇게 하면 **기능은 16가지 그대로** 유지하면서, **보이는 느낌만** “마이 대시보드/진단”과 같은 B2C 영역으로 통일됩니다.

### 3.3 기술적으로 바꾸는 부분 (개발 관점, 요지만)

- **HTML → React**
  - `index.html`의 목록·필터·모달 → 하나의 React 컴포넌트(예: `InbasketList`) 또는 진단 페이지 내 섹션.
  - `simulation.html` + `simulation-content` → 문항 선택 시 보여 주는 **또 다른 섹션** 또는 **하위 컴포넌트** (`InbasketSimulation`). 16가지 타입은 각각 **컴포넌트**로 만듦 (예: `EmailSimulation`, `MessengerSimulation`, …).
- **JS 로직**
  - `main.js`의 문항 로드/필터/모달/시작 → React의 `useState`, `useMemo`, 이벤트 핸들러로 구현. 데이터는 `import ... from '@/data/...'` 형태의 JSON.
  - `simulation.js`의 16개 `renderXXX` 함수 → **16개 React 컴포넌트**로 재작성. 각 컴포넌트는 `question`(문항 데이터)을 props로 받아 같은 UI를 그리되, HTML 문자열 대신 JSX로 작성.
- **스타일**
  - 인라인 Tailwind class는 유지하되, 색·그라데이션만 위 3.2절 규칙으로 교체.
  - `index.html` 상단 `<style>` 블록에 있던 클래스(.gradient-header, .job-pill 등) → Tailwind 유틸 클래스나 `className`으로 대체.
- **데이터**
  - `tables/questions` → `data/kappDiagnosis/inbasket/` 같은 폴더 아래 **타입별 JSON**(예: `email.json`, `messenger.json`, …) 또는 **한 파일에 16타입 더미**를 두고, 진단 5단계에서만 이 데이터를 사용.
- **라우팅**
  - 별도 URL(`/simulation?id=...`) 없이, **진단 페이지 상태**로 “지금 목록 보는 중” vs “지금 시뮬레이션 실행 중(문항 ID)” 구분.

이렇게 하면 “원본 폴더의 동작과 화면 구성”은 유지하면서, **앱 구조·디자인·데이터**만 Next와 B2C 톤에 맞게 이전하는 형태가 됩니다.

### 3.4 배포 시 digital_inbasket 폴더

- **빌드/배포에서만 제외**합니다. (저장소에서 삭제하지 않음.)
- Next 빌드에 `digital_inbasket` 폴더를 포함하지 않도록 설정하고, Vercel 등 배포 설정에서도 해당 경로를 제외하면 됩니다.  
  (예: `.vercelignore`에 `digital_inbasket` 추가. Next가 이 폴더를 참조하지 않으므로, 배포 결과물에는 포함되지 않습니다.)

## 4. 정리 (비개발자용 한 줄 요약)

- **학습자 LMS**: KAPP 진단 **5단계**에서 디지털 인바스켓이 나오고, **16가지 시뮬레이션을 모두 목록으로 보여 주며**, 학습자가 **여러 개**를 골라 풀 수 있게 합니다. (나중에 직무 매핑으로 보이는 개수만 줄일 예정.)
- **원본 폴더**: `index.html` = 목록/필터/모달, `simulation.html` = 타이머+타입별 UI. `main.js`는 목록·필터·시작, `simulation.js`는 16가지 타입별 화면을 그립니다. 디자인은 보라·그라데이션 중심입니다.
- **앱에 넣을 때**: **기능과 16가지 흐름은 유지**하고, **파일은 React/Next로 전환**, **데이터는 JSON/더미로**, **디자인은 마이 대시보드와 같은 밝은 회색·파랑 톤**으로 바꿉니다. **응답 저장은 하지 않고**, **digital_inbasket 폴더는 배포에서만 제외**합니다.

이 문서를 기준으로, 다음 단계에서 **데이터 스키마·폴더 구조**와 **16가지 컴포넌트 목록**을 더 쪼개어 구현 계획에 반영할 수 있습니다.
