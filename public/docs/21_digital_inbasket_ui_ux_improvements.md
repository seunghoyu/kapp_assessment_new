## 1. 전체 톤과 시각적 일관성

### 1.1 색상·강조 체계 통일

| 현상 | 제안 |
|------|------|
| 타입별로 primary 색이 제각각(파랑·빨강·amber·회색) | **공통:** 주요 액션·선택 완료는 `blue-600` 계열 하나로 통일. "긴급/위험"만 `red-500`, "주의"는 `amber-500`로 예외 허용. |
| 배경이 흰색·gray-50·gray-100·gray-800 혼재 | **공통:** 시뮬레이션 본문 배경은 `bg-white` 또는 `bg-gray-50` 중 하나로 통일. 사이드/상황판 다크는 유지해도 되나, 나머지 콘텐츠 영역은 밝은 배경으로 통일. |
| 완료/선택 표시가 초록·파랑·체크 아이콘 혼재 | **완료 표시:** "선택 완료" 뱃지는 `bg-green-100 text-green-800` + CheckCircle 아이콘으로 통일. |

### 1.2 타이포그래피

| 현상 | 제안 |
|------|------|
| 제목 크기·굵기가 타입마다 다름(text-lg·text-xl·font-bold·font-semibold) | **헤더:** 문항/시나리오 제목은 `text-lg font-bold text-gray-900`. 부제는 `text-sm text-gray-600`. |
| 본문·안내 문구가 text-sm·text-xs 혼재 | **본문:** `text-sm text-gray-700`. **보조/캡션:** `text-xs text-gray-500`. |
| 버튼·라벨 폰트 굵기 불일치 | **라벨:** "처리 방법", "우선순위" 등은 `font-medium`. **선택지 버튼:** `font-medium` 통일. |

### 1.3 간격·카드 스타일

| 현상 | 제안 |
|------|------|
| 섹션 간격이 p-4·p-6·mb-4·mb-6 등 혼재 | **섹션 간:** `mb-6` 또는 `space-y-6` 통일. **카드 내부:** `p-4` 통일. |
| 카드 테두리·둥글기가 제각각(border·border-2·rounded-lg·rounded-xl) | **카드:** `border border-gray-200 rounded-xl` + `shadow-sm` 선택. **내부 블록:** `rounded-lg`. |
| 버튼 패딩·크기 차이 | **주요 버튼:** `px-4 py-2.5` 또는 `px-4 py-3`, `rounded-lg`. **작은 액션:** `px-3 py-1.5 text-sm`, `rounded-lg`. |

## 2. 레이아웃·정보 계층

### 2.1 공통 프레임(InbasketSimulation 래퍼)

| 현상 | 제안 |
|------|------|
| "목록으로"만 있고 문맥이 약함 | 상단에 **브레드크럼 또는 문항 요약 한 줄** 유지. 예: "디지털 인바스켓 > [문항 제목]". |
| "완료하고 다음 단계로"가 모든 타입 동일 | 버튼 문구는 유지하되, **미선택 항목이 있으면 비활성화 + 툴팁** "n개 항목을 선택해 주세요"로 명확히. |
| 스크롤 시 헤더가 사라짐 | 상단(목록으로 + 문항 정보)은 `sticky top-0 z-10`으로 고정해, 긴 시뮬레이션에서도 문맥 유지. |

### 2.2 2열·3열 레이아웃

| 현상 | 제안 |
|------|------|
| 좌측 사이드바가 타입마다 너비 다름(w-52·w-72·w-80) | **사이드/패널:** `w-64`(256px) 또는 `min-w-[240px] max-w-[280px]`로 통일. 반응형에서 `md:` 이하에서는 접기 또는 상단 탭으로 전환 검토. |
| 중앙 편집 영역이 좁아 보이는 타입 있음 | **메인 콘텐츠:** `flex-1 min-w-0` 유지하고, `max-w-4xl mx-auto`로 넓은 화면에서도 가독성 확보. |
| 우측 패널(ROI·가이드·디자인)이 일부 타입만 있음 | 패널이 있는 타입은 **패널 너비 통일**(예: `w-64`). 없으면 여백으로 두어 시각적 균형 유지. |

### 2.3 정보 우선순위

| 현상 | 제안 |
|------|------|
| 문항 content가 길어서 "뭘 해야 하지?"가 묻힘 | **상단 고정:** "상황" 1~2문장 + **"아래에서 각 항목의 의사결정을 선택해 주세요"** 한 줄을 타입 공통으로 상단에 배치. |
| 단계가 여러 개인데 번호만 있음 | **다단계 타입:** "1단계 — 즉각 대응 전략"처럼 **번호 + 단계명**을 섹션 제목으로 쓰고, 필요 시 진행률 바(1/4 완료 등) 추가. |

## 3. 입력 요소·인터랙션

### 3.1 버튼 vs 셀렉트

| 현상 | 제안 |
|------|------|
| 같은 "선택"인데 어떤 타입은 버튼, 어떤 타입은 select | **선택지 2~5개:** 버튼 그룹(토글 형태)으로 통일 → 선택 상태가 한눈에 보이고 터치하기 쉬움. **6개 이상:** select 또는 라디오 리스트. |
| 비선택 상태가 회색 배경으로만 구분됨 | **선택됨:** `bg-blue-600 text-white border-blue-600`. **미선택:** `bg-white border-gray-300 text-gray-700 hover:bg-gray-50`. 포커스 링 `focus:ring-2 focus:ring-blue-500` 추가. |

### 3.2 폼 컨트롤

| 현상 | 제안 |
|------|------|
| input/textarea 높이·border 불일치 | **input:** `h-10` 또는 `py-2.5`, `border border-gray-300 rounded-lg`, `focus:border-blue-500 focus:ring-1 focus:ring-blue-500`. **textarea:** 동일 border/radius, `min-h-[80px]`. |
| placeholder가 없거나 타입마다 문체 다름 | **placeholder:** "선택하세요" / "입력하세요(선택)" 등 짧게. 숫자 입력은 "예: 1,500,000" 등 예시 하나만. |
| 라벨이 없거나 작아서 시인성 약함 | **라벨:** `label` 태그 + `font-medium text-gray-700 mb-1` 또는 `mb-1.5`. 필수는 `*` 또는 "(필수)" 표시. |

### 3.3 피드백

| 현상 | 제안 |
|------|------|
| 선택 완료 후 시각적 피드백만 있고 텍스트 없음 | **완료 시:** 카드 테두리 `border-green-500` + "선택 완료" 작은 뱃지 + (선택) 짧은 문구 "답장 · 긴급으로 처리합니다." |
| 오류/경고가 거의 없음 | **예산 초과 등:** 이미 있는 경고(빨간 배경) 유지. **미선택 제출 시:** 버튼 클릭 시 토스트 또는 인라인 메시지 "n개 항목을 선택해 주세요." |
| 로딩·저장 중 상태 없음 | **완료 버튼 클릭 시:** 버튼 비활성화 + "제출 중..." 스피너 또는 문구. 제출 완료 후 목록/다음 단계로 전환. |

## 4. 빈 상태·첫 진입

### 4.1 빈 상태(Empty State)

| 타입 | 현상 | 제안 |
|------|------|------|
| 이메일 관리 | 메일 미선택 시 "이메일을 선택하세요" + 아이콘만 있음 | **일관:** 좌측 목록을 가리키는 화살표 또는 "← 왼쪽 목록에서 메일을 선택하세요" 문구. 아이콘 크기 유지. |
| 기타 | "선택하세요" option만 있는 select 다수 | **최초:** option value="" 에 "선택하세요" 유지. 선택 후에는 선택된 값이 명확히 보이도록(버튼이면 이미 적용됨). |

### 4.2 첫 진입 안내

| 제안 | 설명 |
|------|------|
| **타입별 한 줄 안내** | 시뮬레이션 최상단에 회색 박스로 "이 시나리오에서는 [상황 요약]. 아래 항목을 선택해 의사결정을 완료해 주세요." |
| **진행률 노출** | 다단계 타입(위기·보고서·윤리·고객 등)은 좌측 또는 상단에 "1/4 단계 완료" 등 진행률 표시. |
| **(선택) 짧은 도움말** | 복잡한 타입(보고서·재무·마케팅)만 "예산 초과 시 빨간색으로 표시됩니다" 등 1줄 도움말. |

## 5. 반응형·접근성

### 5.1 반응형

| 현상 | 제안 |
|------|------|
| 2열·3열이 작은 화면에서 겹침 | **breakpoint:** `md` 이하에서 좌측 패널을 상단 탭 또는 아코디언으로 전환. 메인 콘텐츠가 먼저 보이도록. |
| 테이블·카드 그리드가 가로 스크롤 | **카드:** `grid-cols-1 sm:grid-cols-2` 등으로 1열 → 2열. **테이블:** 카드 형태로 전환하거나 가로 스크롤 영역에 `overflow-x-auto` + 최소 너비 명시. |
| 버튼이 너무 작음 | 터치 타겟 최소 44px. `py-2.5` 이상, `min-h-[44px]` 권장. |

### 5.2 접근성

| 제안 | 설명 |
|------|------|
| **포커스 링** | 모든 버튼·링크·input에 `focus:outline-none focus:ring-2 focus:ring-blue-500 focus:ring-offset-2`. |
| **라벨 연결** | input/select/textarea에 `id` 부여 후 `label htmlFor` 연결. 라디오/체크박스는 `label`로 감싸기. |
| **의미 있는 순서** | 키보드 탭 순서가 시각적 순서와 일치하도록. 제목 → 상황 → 1단계 → 2단계 → … → 제출. |
| **색만으로 상태 전달 금지** | "선택 완료"를 초록색만으로 쓰지 말고, 체크 아이콘 + "선택 완료" 텍스트 병기. |

## 6. 타입별 UI·UX 포인트 (요약)

| 카테고리 | UI·UX 개선 포인트 |
|----------|-------------------|
| 이메일 관리 | 빈 상태 안내 강화. 액션/우선순위 버튼 그룹 시각적 구분(액션 1행·우선순위 1행). |
| 메신저 대응 | 긴급 메시지 카드 좌측 뱃지 유지. select → 버튼 그룹 전환 검토(선택 상태 가시성). |
| 보고서 작성 | 리본·디자인 패널이 동작하지 않으면 흐리게 또는 "준비 중" 표시. 진행률 바 위치 통일. |
| 일정 관리 | 회의 카드 시각적 위계(중요 회의가 더 크거나 상단). 라디오 그룹 간격 넓혀 터치하기 쉽게. |
| 통합 업무 | 탭 선택 상태 명확히. "해당 채널 문의 없음"일 때 안내 문구 + 다른 탭 유도. |
| 위기 관리 | 좌측 상황판과 우측 의사결정 영역 시각적 분리 유지. 4단계 번호+제목 강조. |
| 글로벌 협업 | "문서 버전 관리"가 읽기 전용이면 카드 형태로 구분. |
| 법무 검토 | 조항 카드 위험도 색(빨강·노랑·회색) 유지. 버튼 4개 가로 배치 시 작은 화면에서 wrap. |
| 디지털 활용 | 도구 카드 순서·우선순위 번호 크게. "우선순위 1~4" 라벨 명시. |
| 인사 관리 | 갈등 다이어그램 아래 3섹션 구분선 명확히. |
| 재무 관리 | 부서 카드 + 입력 + 버튼이 한 블록 안에 묶이도록. 금액 input 오른쪽 정렬 또는 단위(원) 표시. |
| 고객 관리 | 4블록 그리드에서 라벨(1. 즉각 대응 …) 강조. |
| 윤리 경영 | "조사 범위" 복수 선택임을 "(복수 선택)" 문구로 표시. |
| 전략 기획 | 읽기 전용 섹션과 입력 섹션 시각적 구분(배경색·테두리). |
| 마케팅캠페인 | 예산 현황 4칸과 캠페인 카드 시각적 분리. ROI 패널 고정 너비. |
| 생산관리 | 라인별 상태 뱃지와 조치 버튼 그룹 간격. 가이드 패널 안내 문구 짧게. |

## 7. 요약 체크리스트

- **색·타이포·간격·카드:** 16가지 타입에서 primary 색, 제목/본문 크기, 섹션 간격, 카드 스타일 통일.
- **레이아웃:** 공통 상단(목록으로+문항) 고정, 사이드/패널 너비 통일, 상단 "상황+안내" 한 줄.
- **입력:** 선택지는 2~5개면 버튼 그룹, 6개 이상은 select/라디오. 라벨·placeholder·포커스 링 적용.
- **피드백:** 선택 완료 시 초록 테두리+뱃지+아이콘 통일. 제출 시 버튼 로딩·미선택 시 안내 메시지.
- **빈 상태·첫 진입:** 이메일 미선택 안내 강화, 타입별 한 줄 시나리오 안내, 다단계 진행률 노출.
- **반응형·접근성:** md 이하에서 패널 전환, 터치 타겟 44px, focus ring·라벨·키보드 순서 점검.
