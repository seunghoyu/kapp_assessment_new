# DOM 구조도 생성 템플릿 & 작성 원칙 (Prompt 학습용)

본 문서는 **첨부 예시 이미지처럼 "DOM 트리 구조도"를 일관된 형식으로 생성**하기 위한 템플릿/원칙입니다.  
목표는 "HTML 문서의 구조 + 노드 유형(element/text/attribute) + 연결 관계"를 **시각화 가능한 규격**으로 정리하는 것입니다.

---

## 1) 산출물 목표 (Outcome)

DOM 구조도는 아래를 한 눈에 보여야 합니다.

- **문서 루트**: `document` → `<html>`을 최상단으로 표시
- **계층 구조**: 부모-자식 관계를 트리로 표현
- **노드 타입 구분**:  
  - Element node: 태그(`<div>`, `<head>`, `<body>` 등)
  - Text node: 텍스트 컨텐츠(예: "결제 프로젝트")
  - Attribute node: `id`, `class`, `data-*` 등 속성
- **속성 연결**: 해당 element에서 attribute로 "옆으로" 연결(트리 자식처럼 보이지 않게)

---

## 2) 노드 타입 표준 (필수 규칙)

### 2.1 Element node
- 표기: `<tag>` 형태로 통일 (예: `<div>`, `<header>`)
- 필요 시 보조 라벨 허용:
  - `<div#app>` (id가 핵심일 때)
  - `<button.primary>` (class가 핵심일 때)
  - 단, **과도한 class 나열 금지** (최대 1~2개까지만)

### 2.2 Text node
- 표기: 따옴표 없는 "텍스트 원문" 그대로
- 노드로 분리 기준:
  - 사용자에게 실제로 보이는 텍스트만
  - 공백/줄바꿈만 있는 텍스트 노드는 **생략**
- 예: `결제 프로젝트`, `로그인`, `저장`

### 2.3 Attribute node
- 표기: 속성명만 표시 (예: `id`, `class`, `data-company`)
- 값 표기 규칙(선택):
  - 기본은 속성명만 `id`
  - 값이 구조 이해에 중요하면 `id="app"` 같이 표시
- 연결 규칙:
  - attribute node는 **트리의 자식이 아니라 "측면 연결"**로 표현
  - 한 요소에 속성이 많으면 우선순위만 표시(아래 4.3 참고)

---

## 3) 레이아웃 원칙 (예시 이미지 스타일 기준)

### 3.1 영역(그룹) 3분할
구조도는 가능한 아래 3영역을 분리해 배치합니다.

- **element node 영역**: 트리 본체
- **text node 영역**: 텍스트 노드를 별도 라인/박스로 모아 표시
- **attribute node 영역**: 속성 노드를 우측 박스로 모아 표시

> 목적: 트리(구조)와 데이터(텍스트/속성)를 시각적으로 분리해 가독성을 확보

### 3.2 트리 정렬
- 상단: `document`
- 다음: `<html>`
- 그 아래: `<head>` / `<body>`를 좌우로 배치(가능하면)
- 깊이가 깊어지면:
  - "같은 부모 아래 자식들은 같은 레벨"로 수평 정렬
  - 너무 넓어지면 좌측부터 순차 배치하되, 부모-자식 선이 겹치지 않게

### 3.3 연결선 규칙
- 부모 → 자식: 수직/ㄴ자 연결
- 요소 → 속성: 수평 연결(옆 박스 방향)

---

## 4) 간소화 규칙 (실무용 핵심)

### 4.1 "보여줄 가치" 기준
다음은 우선 표시합니다.
- 레이아웃/구획 태그: `<header> <main> <section> <nav> <footer>`
- 기능 포인트: `<form> <input> <button> <a>`
- 데이터 바인딩 지점: `id`, `data-*`, 주요 class(1~2개)

### 4.2 생략 기준
- 시각적 구조와 무관한 래퍼 `<div>`가 과도하면 중간 레벨 일부 생략 가능
  - 단, 생략 시 부모-자식 관계가 왜곡되지 않도록 "…" 노드 사용 가능
- 반복되는 리스트 항목(예: `<li>` 20개):
  - 대표 1개만 표시 + `(x20)` 같은 수량 표기

### 4.3 Attribute 우선순위
속성이 많을 때는 아래 우선순위로 최대 3개까지만 표시:
1) `id`
2) `data-*` (업무 키/식별에 쓰일 때)
3) 핵심 `class` (UI 상태/역할을 구분할 때)

## 5) 입력 포맷(요구사항) 템플릿

DOM 구조도를 만들기 위해, 아래 정보를 입력으로 받습니다.

### 5.1 필수 입력
- 페이지/화면 이름:
- 최상위 컨테이너(예: `#app`, `#root`):
- 주요 섹션 목록(예: Header/Main/Footer):
- 각 섹션의 핵심 UI 컴포넌트(버튼/폼/리스트 등):
- 사용자에게 보이는 주요 텍스트(라벨/버튼명/타이틀):

### 5.2 선택 입력
- 마스킹/권한 등 정책에 따른 표시 제한 요소:
- 데이터 키(예: `data-company-id`, `data-user-id`):
- 반복 요소 수량(리스트/테이블):

## 6) 출력 포맷(산출물) 템플릿

산출물은 "텍스트 기반 구조도"로 먼저 만들고, 이후 이미지/도식화로 변환하는 것을 권장합니다.

### 6.1 텍스트 DOM 구조도 (표준)
- 들여쓰기: 2 spaces
- element는 `<tag>`로 표기
- attribute는 `@attr`로 표기하고, 옆 연결 대상임을 주석 처리
- text는 `"텍스트"` 대신 그냥 텍스트로 표기 (구분 필요 시 `#text:` 접두어 사용)

예시:
- document
  - <html>
    - <head>
      - <meta>      @charset
      - <title>
        - #text: 결제 프로젝트
    - <body>
      - <div>       @id="app"  @class="container"
        - <header>
        - <main>
          - <button> @class="primary"
            - #text: 저장

### 6.2 구조 요약(선택)
- "핵심 노드 5개" 요약
- "속성(식별자) 목록" 요약
- "텍스트 노드 목록" 요약

## 7) 프롬프트 작성 규칙 (GPT/툴 학습용)

아래 프롬프트 규격으로 요청하면 결과가 일관됩니다.

### 7.1 프롬프트 골격
- 목표: "예시 이미지 형식의 DOM 구조도"
- 출력: "텍스트 DOM 구조도" + "요약" (선택)
- 규칙: 노드 타입/간소화/속성 우선순위 적용

### 7.2 프롬프트 템플릿
아래를 복사해 사용:

[요청]
- 아래 화면 요구사항을 기반으로, 예시 이미지 스타일의 DOM 구조도를 생성해줘.
- element node / text node / attribute node를 구분해줘.
- attribute는 트리 자식이 아니라, 해당 element에서 측면 연결되는 형태로 표현해줘.
- 불필요한 래퍼 div는 생략 가능하되, 구조가 이해되게 유지해줘.
- 반복 요소는 대표 1개만 표시하고 수량을 표기해줘.

[입력]
- 화면명:
- 주요 섹션:
- 핵심 컴포넌트:
- 주요 텍스트:
- 중요한 속성(id/data/class):

[출력]
1) 텍스트 DOM 구조도(표준 포맷)
2) (선택) 핵심 노드/속성/텍스트 요약

## 8) 체크리스트 (결과 검수용)

- [ ] 최상단이 `document → <html>`로 시작하는가?
- [ ] `<head>` / `<body>`가 적절히 분리되었는가?
- [ ] text node가 "보이는 텍스트 중심"으로만 포함됐는가?
- [ ] attribute node가 측면 연결 대상으로 처리됐는가?
- [ ] 속성이 과도하게 나열되지 않았는가(우선순위 3개 이내)?
- [ ] 반복 요소가 축약 표기 되었는가?
- [ ] 구조가 화면 이해에 충분한가(과생략/과상세 아닌가)?

---

## 9) 예시 입력/출력 (미니 샘플)

### 입력
- 화면명: 결제 프로젝트
- 주요 섹션: Header / Main
- 핵심 컴포넌트: 결제버튼, 결제내역 리스트
- 주요 텍스트: 결제 프로젝트, 결제하기
- 중요한 속성: #app, data-order-id

### 출력(예시)
- document
  - <html>
    - <head>
      - <title>
        - #text: 결제 프로젝트
    - <body>
      - <div>         @id="app"
        - <header>
          - <h1>
            - #text: 결제 프로젝트
        - <main>
          - <button>   @class="primary"
            - #text: 결제하기
          - <ul>
            - <li>     @data-order-id="..."
              - #text: (결제내역 항목) (xN)
